## Summary

There are **two** production paths that write the three delta fields, and they are shaped
differently:

| Path | Fn | Where `Some(..)` is built | Where the fields are written | None reset |
| --- | --- | --- | --- | --- |
| Governor | `run_governor_cycle` | helper `window_deltas_from_snapshots` @ **1245** | **4204–4206**, unconditional | `_ => (None, None, None)` @ **1253** (no `else` at the call site) |
| Observe | `run_observe_cycle_internal` | inline @ **6037–6039** | same lines, inside `if let (Some, Some)` | **explicit `else` @ 6040–6052, clearing all three @ 6045–6047** |

Both are correct, and **no crossed wires were found on either path**.

### Else-branch None reset: **PRESENT**

Stated explicitly per the acceptance criteria. The `else` at **6040** assigns `None` to
all three fields at **6045–6047**, with a comment ("Clear every delta field explicitly so
a stale `Some(..)` from an earlier cycle is not mistaken for a reading of the current
interval. Mirrors run_governor_cycle."). All three fields are covered — none is left to
carry a stale value from a previous cycle.

## 2. The governor path — same guarantee, different shape

`run_governor_cycle` does **not** contain an `if let (Some, Some)` / `else` pair. It calls
the helper at **4174–4177** and assigns the returned `Option`s unconditionally:

```rust
4174            let (p5h_delta, p7d_delta, p7ds_delta) = window_deltas_from_snapshots(
4175                state.previous_api_snapshot.as_ref(),
4176                state.current_api_snapshot.as_ref(),
4177            );
...
4201            // Assign unconditionally: on the no-baseline path these are None, so
4202            // a stale Some(..) from the previous cycle cannot survive into an
4203            // interval it does not describe.
4204            state.p5h_delta  = p5h_delta;
4205            state.p7d_delta  = p7d_delta;
4206            state.p7ds_delta = p7ds_delta;
```

So on this path the answer to "is there an else branch assigning None?" is: **no else
branch exists, and none is needed.** The `None` case is produced inside the helper by
`_ => (None, None, None)` at **1253** and then written by the same unconditional
assignments at 4204–4206. The reset guarantee is identical to the observe path's `else`.

Pairing on this path is positional in two hops and is also correct:
`window_deltas_from_snapshots` returns `(Some(delta_5h), Some(delta_7d), Some(delta_7ds))`
at **1245** in that order, the tuple is destructured into like-named locals at 4174, and
each local goes to its matching field at 4204/4205/4206. The `match` at 4179–4199 that sits
between the call and the assignments is **logging only** — every arm's body is a
`log::info!` / `log::debug!`; it rebinds `delta_5h`/`delta_7d`/`delta_7ds` in the arm
pattern at 4186 but writes nothing, so it cannot reorder or drop a field.

## Verdict

- Three `Some(..)` assignments inside the block: **CONFIRMED** (6037, 6038, 6039).
- Field-to-delta pairing: **CONFIRMED** for all three, on both production paths.
- Else-branch `None` reset: **PRESENT** on the observe path (6040 → 6045–6047).
  **ABSENT by design** on the governor path, where unconditional assignment at 4204–4206
  plus the helper's `_ => (None, None, None)` at 1253 gives the same guarantee.
- Production assignments outside the block: **one** — 4204–4206 in `run_governor_cycle`
  (correct, and the reason the observe-path code carries a "Mirrors run_governor_cycle"
  comment). Everything else is test code or the `Default` impl.

## Carry-forward (not a defect, no change made here)

The observe path duplicates the delta decision inline instead of calling
`window_deltas_from_snapshots`. Same observation bf-1m3ux and bf-4xxa6 recorded. Both
copies are currently correct and in agreement; the risk is drift, since a fix to the
helper would silently not reach `run_observe_cycle_internal`. Routing 6015–6052 through
the helper would collapse it to the same three-line unconditional assignment used at
4204–4206.
